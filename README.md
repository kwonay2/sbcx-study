# 2조 SBCX 실험 플랫폼

참가자 화면, 관리자 화면, 구글 시트 저장을 한 사이트에 담은 실험 플랫폼이에요.

| 주소 | 누가 | 무엇 |
|---|---|---|
| `https://<내 사이트>.vercel.app/` | 참가자 | 동의 → 사전 설문 → 상황 카드 → 과업 2번(▼T1·▼T2 질문) → 마지막 질문 → 디브리핑 → 추첨 번호 |
| `https://<내 사이트>.vercel.app/admin` | 연구팀 4명 | 현황 · 응답 목록 · 행동 로그 · 동의 기록 · 문항 사전 · 관리 도구 · 엑셀 내려받기 |

응답과 행동 로그는 **구글 시트**에 쌓이고, 추첨용 휴대전화 번호는 응답과 연결되지 않게 **별도 구글 시트 파일**에 참가자 ID 없이 저장돼요.

```
참가자 브라우저 ──▶ Vercel 사이트 (/api) ──비밀 키──▶ Apps Script 웹 앱 ──▶ 구글 시트
```

참가자 브라우저는 구글 시트 주소나 비밀 키를 모르고, 배정·구분 같은 열은 서버만 쓸 수 있어요.

---

## 1. 구글 시트 준비 (한 번, 약 10분)

1. 연구팀 구글 계정으로 [새 구글 시트](https://sheets.new)를 만들고 이름을 `SBCX 실험 데이터`로 바꿔요.
2. 메뉴 **확장 프로그램 → Apps Script**를 열어요.
3. 왼쪽 `Code.gs`의 내용을 모두 지우고, 이 폴더의 `apps-script/Code.gs`를 통째로 붙여 넣은 뒤 저장 아이콘을 눌러요.
4. 위쪽 함수 목록에서 **`setup`** 을 고르고 **실행**을 눌러요.
   - 권한 검토 → 계정 선택 → “Google에서 확인하지 않은 앱” 화면이 나오면 **고급 → (안전하지 않음)으로 이동 → 허용**. 우리 팀이 만든 스크립트라서 나오는 안내예요.
   - 아래 **실행 로그**에 `APPS_SCRIPT_SECRET = …` 가 나와요. 이 값을 복사해 두세요.
   - 같은 로그에 나온 ‘추첨 번호 시트’ 주소가 별도로 만들어진 번호 보관 파일이에요.
5. 오른쪽 위 **배포 → 새 배포** → 톱니바퀴에서 **웹 앱**을 고르고
   - 다음 사용자 인증 정보로 실행: **나**
   - 액세스 권한이 있는 사용자: **모든 사용자**
   - **배포** → 나온 **웹 앱 URL**(`…/exec`로 끝남)을 복사해요.

> 액세스 권한을 “모든 사용자”로 해도 비밀 키가 없으면 아무것도 읽거나 쓸 수 없어요.
> `Code.gs`를 고친 뒤에는 **배포 → 배포 관리 → 연필 아이콘 → 버전: 새 버전 → 배포**를 해야 반영돼요. (URL은 그대로)

## 2. Vercel에 올리기 (한 번)

1. 이 폴더를 GitHub 새 저장소(비공개 권장)에 올려요. `node_modules`, `.data`, `dist`는 올리지 않아요(`.gitignore`에 있음).
2. [vercel.com](https://vercel.com) → **Add New → Project** → 그 저장소 **Import**. Framework Preset은 **Vite**로 자동 선택돼요.
3. **Environment Variables**에 네 가지를 넣어요. (`.env.example` 참고)

   | 이름 | 값 |
   |---|---|
   | `APPS_SCRIPT_URL` | 1-5에서 복사한 웹 앱 URL |
   | `APPS_SCRIPT_SECRET` | 1-4에서 복사한 값 |
   | `ADMIN_PASSWORD` | 관리자 화면 비밀번호 (팀원끼리만 공유) |
   | `SESSION_SECRET` | 아무 긴 무작위 문자열 (32자 이상) |

4. **Deploy**. 환경 변수를 나중에 바꾸면 **Deployments → … → Redeploy**를 해야 적용돼요.
5. 프로젝트 이름을 `moa-study` 처럼 정하면 주소가 `moa-study.vercel.app`이 돼요.

## 3. 첫 점검 (배포 직후)

1. `/admin`에 들어가 비밀번호로 로그인 → 위쪽에 “로컬 개발 모드” 안내가 **없으면** 구글 시트에 연결된 거예요.
2. **관리 도구 → 조건 미리보기**에서 집단 1~4 × 결정 먼저/행동 먼저 링크로 C1~C4를 끝까지 해 봐요. 이 링크(`?test=1`)로 들어온 응답은 ‘테스트’로 저장돼요.
   - 같은 브라우저에서는 진행 상황이 이어지므로, 다른 조건을 보려면 화면 위쪽 **[처음부터 다시]** 를 눌러요.
   - “시간 짧게”를 켜면 도움말 10초 · 건너뛰기 20초 · 상황 카드 2초로 빨리 볼 수 있어요.
3. 구글 시트 `응답`, `행동 로그`, `동의 기록` 탭에 줄이 생겼는지, **응답 목록 → 엑셀 내려받기**가 되는지 확인해요.
4. 확인이 끝나면 **관리 도구 → 테스트 응답 지우기**.

## 4. 파일럿 → 본실험

1. **관리 도구 → 모드: 파일럿 → 설정 저장**. 이때부터 들어오는 사람은 ‘파일럿’으로 저장되고, 배정 균형도 본실험과 따로 세요.
2. 파일럿 16~20명에게 참가자 링크(`/`)를 보내요. 끝나면 계획서 기준(조작점검, 신뢰도, 소요 시간 등)을 엑셀로 확인해요.
3. 제한 시간(90초 등)을 바꿔야 하면 같은 화면에서 바꾸고 저장해요. 새로 시작하는 참가자부터 적용돼요.
4. **모드: 본실험 → 설정 저장** 후 모집을 시작해요. 현황 탭에서 집단별 완료 인원(목표 45명)과 성비·나이를 모집 중간에 확인해요.

## 5. 동작 규칙 (계획서 반영)

- **배정**: 동의 후 익명 ID(`P-XXXXXX`)를 만들고, 집단 4 × 결정·행동 순서 2 × 니트 세트 순서 2 = **16칸 중 가장 적은 칸**에 무작위로 넣어요. 같은 구분(본실험/파일럿) 안에서 ‘완료했거나 30분 안에 움직인 사람’만 세므로, 중도 이탈한 자리는 다시 채워져요.
- **화면**: 왼쪽 휴대폰 프레임(390×844 비율, 창 높이에 맞춰 축소) + 오른쪽 연구 패널. ★칸만 C1~C4에 따라 달라요. [다시 추천받기]를 누르면 앱이 그 화면 그대로 잠기고 ▼T1(M1 → M2), [완료]를 누르면 ▼T2(Y3 → Y1 → Y2+결과 만족), 그다음 조작점검. 과업당 6화면.
- **질문**: 변수당 한 화면, 7점 가로 버튼, 필수 응답, 뒤로 가기 없음, 화면 안 문항 순서는 참가자마다 섞음(결과 만족은 Y2 뒤, 조작점검은 고정). 주의 점검(29번)은 과업 2의 Y1 화면에 한 번.
- **도움말**: 혼자 찾기 제한 시간(기본 90초, 화면을 보고 있을 때만 흐름)이 지나도 기능을 못 찾으면 오른쪽에 도움말, 앱에는 위치 테두리. 그 뒤 3분이 지나도 못 바꾸면 [건너뛰기] → ▼T2로, `task1_skip = 1`(미사용).
- **저장**: 화면을 넘길 때마다 저장하고, 행동 로그는 15초마다·40건마다·창을 숨기거나 닫을 때(sendBeacon) 보내요. 연결이 끊기면 다시 시도하고, 마지막 화면은 저장이 확인될 때까지 “저장 중”으로 보여요.
- **새로고침**: 같은 브라우저에서 새로고침하거나 다시 열면 같은 ID로 그 화면부터 이어서 해요(로그에 `resume`).
- **중복 참여**: 본실험·파일럿을 끝낸 브라우저로 다시 들어오면 “이미 참여하신 기기예요”가 나와요. (브라우저를 바꾸면 막을 수 없으니 추첨 때 번호 중복도 확인)
- **기기**: 휴대폰이나 가로 768px 미만이면 “PC로 접속해 주세요”와 링크 복사 버튼, 1280px 미만이면 창을 키워 달라는 안내.
- **상태**(관리자 화면·엑셀): 진행 중 / 완료 / 중단(30분 넘게 반응 없음) / 제외 후보(주의 점검 실패, 또는 완료자 5명 이상일 때 소요 시간이 중앙값의 1/3 미만). 데이터를 지우지 않고 표시만 해요.

## 6. 데이터

구글 시트 탭과 엑셀 내려받기 시트가 같은 구성이에요.

| 시트 | 한 줄 = | 내용 |
|---|---|---|
| 응답 | 한 참가자 | 배정, 진행 상태, 과업별 행동 요약, 문항 31개(과업 문항은 두 번) |
| 행동 로그 | 한 이벤트 | 화면 진입, 응답(누른 시각), 기능 발견, 제외·조건 변경, 다시 추천받기, 도움말, 되돌리기, 완료, 창 숨김 등 |
| 동의 기록 | 한 참가자 | 동의 시각, 문구 버전, 항목별 동의 |
| 문항 사전 | 한 열 | 열 이름 ↔ 시점 · 변수 · 문구 · 응답 형식 · 역코딩 |
| 과업별(긴 형식) | 한 참가자 × 한 과업 | 엑셀에만. 다층모형용 (x1, 조건, 행동 요약, q8~q29, 사전 변수) |
| 동의문 원문 | 한 버전 | 버전별 동의 문구 전문 |

- 열 이름은 SPSS·jamovi에서 바로 쓰게 영문이에요. 사전·마지막 문항은 `q1`~`q7`, `q30`, `q31`, 과업 문항은 `task1_q8`처럼 **과업 순서**를 붙였어요. 결정·행동은 `task1_x1`, `task2_x1` 열로 구분해요.
- 역문항(10·16·19)은 **원점수**로 저장돼요. 분석할 때 `8 − 점수`.
- `attn_pass`는 `task2_q29 = 5`이면 1이에요.
- 날짜·시각은 한국 시간이에요.

## 8. 내 컴퓨터에서 돌려 보기

Node.js 18 이상이 필요해요.

```bash
npm install
npm run dev          # http://localhost:5173  ·  관리자: http://localhost:5173/admin (비밀번호 sbcx-local)
npm run test:storage # Code.gs 저장 로직 점검 (배정 균형, 글자 보존, 추첨 번호 분리, 테스트 삭제)
```

환경 변수가 없으면 구글 시트 대신 `.data/local-sheets.json` 파일에 같은 방식으로 저장돼요(`Code.gs`를 그대로 실행). `.env.local`에 `APPS_SCRIPT_URL`과 `APPS_SCRIPT_SECRET`을 넣으면 내 컴퓨터에서도 실제 구글 시트로 저장돼요. (`.env.local`에 `ADMIN_PASSWORD`를 넣으면 로컬 관리자 비밀번호도 그 값으로 바뀌어요)

## 9. 아직 정해야 하는 것

- 동의 문구 확정(학교 연구 동의 기준) → `CONSENT_VERSION`을 `v1`로
- 디브리핑의 `[연구팀 연락처]`
- 상품 사진·상품 풀(D11): 지금은 회색 니트 실루엣 자리표시와 임시 상품명·가격
- 가상 앱 이름 ‘모아’와 로고, 90초 제한 시간(파일럿 후)

## 10. 문제가 생기면

| 증상 | 확인할 것 |
|---|---|
| 참가자 화면에서 “시작하지 못했어요” | Vercel 환경 변수 4개가 있는지, 넣은 뒤 Redeploy 했는지 |
| “Apps Script 비밀 키가 맞지 않아요” | `APPS_SCRIPT_SECRET`이 실행 로그의 값과 같은지 |
| “JSON이 아닌 응답을 보냈어요” | 웹 앱 액세스 권한이 **모든 사용자**인지, Code.gs를 고친 뒤 **새 버전**으로 배포했는지 |
| 관리자 로그인이 안 돼요 | `ADMIN_PASSWORD`를 넣고 Redeploy 했는지 |
| 엑셀이 느려요 | 행동 로그가 수만 줄이면 몇 초 걸려요. 상태·구분 필터로 줄여서 받아요 |
